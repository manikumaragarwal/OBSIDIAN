# The Agentic Engineering Framework: 4 Mandatory Documents For Successful Vibe Coding

Vibecoding fails when it relies on "Prompt and Pray." To build production-ready applications (like a 48-hour iOS app), an engineer must use a four-document framework that provides the AI with strict structural and logical boundaries.

## Breakdown
1. **PRD (Product Requirements Document):** Defines what the app is and, crucially, what it is NOT. This prevents scope creep and "Spaghetti logic."
2. **Architecture Doc:** Instructs the AI on exactly how to organize folders and data structures to ensure long-term maintainability.
3. **AI Rules Doc:** The non-negotiables (e.g., "Use Swift UI only," "Use Keychain for secrets"). This acts as the automated quality control layer.
4. **The Plan:** A step-by-step roadmap that forces the AI to tackle one task at a time, preventing it from getting lost in complex codebases.

## The Why
AI is an exceptional executor but a poor architect. By providing the architecture and rules in document form, you are removing the "Reasoning Burden" from the AI, allowing it to focus entirely on implementation within the safe zones you have defined.
